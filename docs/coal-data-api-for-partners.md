# 煤库数据写入指南（给协作方）

> 这份文档是自包含的。把它连同密钥一起交给执行方即可，不需要访问代码仓库。

你要做的事：把煤矿调研表（xlsx）里的化验指标，通过 HTTP 接口补进豆哥配煤的煤库。

---

## 0. 先理解：煤库是两层的

```
GET /api/master
    基线 coal_master.json     编译进程序，走 git，人工审阅过
  + 覆盖层 coal_overrides      本接口写这里，立即生效
  = 返回给前端
```

你只能写覆盖层，而且**只能填基线缺的指标**。基线已有值的一律拒绝。

好处是可逆：删掉覆盖层一行 = 回滚一个值，清空整表 = 回到 git 里那份基线。所以写错了不会造成不可逆后果——但也别指望"先写了再说"，被拒的都是有理由的。

---

## 1. 接口

```
POST https://doudou-blend.up.railway.app/api/master/coals
Header: X-API-Key: <密钥>
Header: Content-Type: application/json
```

请求体：

```json
{
  "updates": [
    { "coal": "铁新", "field": "Y",   "value": 16,
      "source": "2026-09-17 Mysteel 规格 Y≥16",   "confidence": "medium" },
    { "coal": "铁新", "field": "CSR", "value": 60,
      "source": "2026-09-17 Mysteel 规格 CSR≥60", "confidence": "medium" }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `coal` | 是 | 煤名，**必须已存在于基线**。本接口不新增煤源 |
| `field` | 是 | `S` / `A` / `V` / `G` / `Y` / `petro` / `CSR` / `M` |
| `value` | 是 | 数值，必须在物理量程内（见 §3） |
| `source` | 是 | 来源与口径，≤200 字符。**原样保留 `≥` / `≤` 符号** |
| `confidence` | 否 | `high` 实测化验单 / `medium` 规格界限 / `low` 区域参考。默认 `medium` |

限制：单批 ≤300 条，请求体 ≤256KB。

**不要填 `updated_by`**——服务端从密钥推导。成功响应会回显身份：

```json
{"ok": true, "applied": 2, "updated_by": "张三-调研"}
```

## 2. 四条硬规则

违反会被拒绝。**不要试图绕过**——每条都有具体理由。

### ① 只填空，不覆盖

基线已有的指标一律 `422`。

原因：基线里的值多是人工核过的**实测化验单**，而调研表推来的多是 Mysteel **规格界限**（`≥` / `≤`）。让界限值盖过实测值，配煤求解器会以为配方合规、而实际不合规。

要修正基线已有的值 → **报告给人**，走人工审阅提 PR。

### ② 整批校验

任何一条不合法，**整批都不写**。半批生效会让你分不清实际状态。修完再整批重发。

### ③ 数值必须在物理量程内

| 指标 | 量程 | 指标 | 量程 |
|------|------|------|------|
| S 硫 | 0 – 10 | Y 胶质 | 0 – 50 |
| A 灰 | 0 – 50 | **petro 岩相** | **0 – 1** |
| V 挥发 | 0 – 50 | CSR | 0 – 100 |
| G 粘结 | 0 – 100 | M 水分 | 0 – 30 |

### ④ `source` 要保留原始符号

`"Y≥16"` 和 `"Y=16"` 是两回事：前者是规格下限，后者是实测。把原始写法留在 `source` 里，日后才分得清这个数的可信度。

## 3. 错误码

| 码 | 含义 | 你该做什么 |
|----|------|-----------|
| `200` | 成功 | 读 `applied` 确认条数 |
| `401` | 密钥无效或已销毁 | **不要重试**，报告给人 |
| `422` | 数据不合法（整批未写） | 按 `errors` 逐条修，剔掉修不了的，整批重发 |
| `400` | JSON 不合法或超 256KB | 检查序列化；太大就拆批 |
| `503` | 数据库不可用 | 指数退避重试，不要改数据 |

**`422` 是正常工况。** 一份新调研表里多数指标基线已经有了，所以被拒很常见——它在告诉你哪些是重复的。正确反应是剔掉被拒条目、保留剩下的重发，而不是放弃整批或想办法绕过。

`errors` 长这样：

```json
{"ok": false, "errors": [
  "第 1 条 (临北/S): 基线已有该指标 (=2), 本接口只补空缺; 要修正已有值请改 coal_master.json 并提 PR",
  "第 3 条 (大佛寺/petro): 2026 超出物理量程 [0, 1]"
]}
```

## 4. 解析调研表时的已知陷阱

以下都是真实发生过的，写在这里省得再踩。

### 岩相列极易被污染

某版调研表 15 个岩相值里 **11 个是年份 `2026`**，其余是 `10.5` / `2200` / `9`。

同行的 Y/CSR/M 却都是对的——所以不是串列，是这一列单独坏了。岩相是反射率分布度量，真实值在 **0.07–0.13**。

**发现该列有 >1 的值 → 整列跳过**，不要逐个猜哪些能用。

### 运费不能当 `frt` 提交

调研表里的运费是「孝义—日照港 165」这类**矿区到外省港口**的区域行情，而系统里 `frt` 指的是运到用户焦化厂的运费。语义不同，混进去会让到厂价算错。

本接口也不接受运费字段。

### 区间值按方向保守取端

`12-16` 这种范围：

- 越大越好的指标（`G` / `Y` / `CSR`）取**下界**
- 越小越好的指标（`S` / `A` / `V` / `M`）取**上界**
- 标 `confidence: "low"`

**宁可低估质量，不可高估。**

不等式值取所给边界即可（`≥16` → `16`），标 `confidence: "medium"`。

### 实测值优先于规格界限

若某煤的备注里有实测值，而调研表给的是规格界限，且两者矛盾——例如备注写着「水分 11.2%」但规格是 `M≤10`——

**停下来问人，不要自己选一个。** 填 10 会让求解器以为水分合规，可记录在案的 11.2 恰恰超标。

## 5. 工作流程要求

**提交前先输出一份清单给人确认**，包含：

1. 准备写入多少条，涉及哪些煤
2. 每条的 `field` / `value` / `source`
3. **你主动跳过了哪些，为什么**

确认后再发请求。

理由：接口能挡住"不合法"的数据，但挡不住**"合法但错误"**的数据——比如岩相填 0.9，在量程内，但明显不对。这份清单是机器校验之外唯一的人工关口。

## 6. 查询与回滚

```bash
# 看覆盖层里现在有什么（排查"这个值哪来的"）
curl https://doudou-blend.up.railway.app/api/master/overrides -H "X-API-Key: $KEY"

# 回滚一个值到基线状态
curl -X DELETE "https://doudou-blend.up.railway.app/api/master/coals/铁新/CSR" -H "X-API-Key: $KEY"
```

覆盖层里没有这一条时返回 `404`。
