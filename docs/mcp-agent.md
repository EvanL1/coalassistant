# 在手机 Agent (Kimi 等) 里用豆哥配煤

> 给同事看的接入说明。不需要装任何东西，只要一个支持 MCP 的 App 和一把密钥。

## 1. 拿密钥

找管理员在后台「API 密钥」里生成一把，用途选 **手机 Agent (只读+求解)**，名字写你的名字
(如「李四-手机」)。密钥只显示一次，管理员当场发给你。

这把密钥**只能查和算**，改不了煤池、合同和煤库。丢了告诉管理员销毁重建即可。

## 2. 在 App 里添加 MCP 服务

| 项 | 填什么 |
|----|--------|
| 类型 | Streamable HTTP (有的 App 叫 "HTTP" / "远程") |
| 地址 | `https://doudou-blend.up.railway.app/mcp` |
| 请求头 | `Authorization: Bearer <你的密钥>` |

App 只让填一个地址、不能设请求头时，地址改填
`https://doudou-blend.up.railway.app/mcp/<你的密钥>` —— 这个地址本身就是密钥，别发群里。

## 3. 能做什么

直接用中文说就行，例如：

- 「按今天的合同算个配方」 → `today_blend`
- 「雪坪停了，不用它再算一次」 → `today_blend`，把雪坪放进 exclude
- 「明鑫 4 份、豹子沟 2 份、大佛寺工程煤 3 份，验算一下」 → `check_ratios`
- 「老母坡筛精是什么煤」 → `find_coal`
- 「现在合同要求是多少」 → `get_contract`

| 工具 | 作用 |
|------|------|
| `today_blend` | 按线上保存的合同与煤池，求最低成本配方：配比 (带煤种)、吨数、每种煤估算价、成本、8 项指标；另附「估价可靠度」—— 哪几种煤的价格差一点配方就会变 (值得先问价)，以及多花不超过 10 元/吨、更多用价格有把握的煤的「更稳的配方」 |
| `check_ratios` | 按给定配比验算成本与指标 |
| `find_coal` | 查煤：状态、煤种、产地、指标 (标出哪些是规格值)、质量指数与估算价 (对标的基准报价) |
| `get_contract` | 当前合同要求、采购吨数、估价用的分煤种基准报价 |

## 4. 口径 (和网页今日屏一致)

- 合同、煤池 (启用/隐藏/改过的指标) 用网页上保存的那一份 —— 要换合同，在网页「合同」里改。
- 所有煤价都是**估算价**：找同煤种、指标最接近的一条**基准报价** (公开的分煤种出厂含税价，带日期)，
  按 1000 点质量指数之比换算 —— 估算价 = 基准价 × 本煤质量指数 ÷ 基准品质量指数。基准报价比焦煤现货
  指数最新一期旧时，按指数涨跌推算到今天。管理员可在后台「基准报价」补录新报价。估算价有误差，下单前要问实价。
- 已停用的煤 (停产、拉不出来) 不会进配方。
- 网页的「采购扣款模板」只存在浏览器里，Agent 这边不计买入侧扣款，结果里会提示。

## 5. 给开发者

- 入口：`POST /mcp` (或 `/mcp/{key}`)，无状态 JSON-RPC，只回 JSON，`GET` 回 405。
- 鉴权：`data_api_keys` 里 `scope = 'mcp'` 的密钥；`data` 用途的密钥 (写煤库) 进不来，反之亦然。
- 请求组装：`blend_kit_server/src/today.rs`，规则对照前端 `domain/resolvedCoal.ts`；协议与排版：`src/mcp.rs`。
