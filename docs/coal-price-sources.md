# 焦煤价格数据源

本文档记录 `IndexTicker`(行情窄条)和成本卡"预测到厂价"用到的两个外部数据源,
是逆向探测得来的**非公开接口**,官方不提供文档也不保证稳定,记下来避免以后
重新翻一遍网络面板。

## 1. 东财焦煤/焦炭期货主连 — `index_quote.ts`

```
实时: https://push2.eastmoney.com/api/qt/stock/get?secid=114.jmm&fields=f43,f58,f59,f169,f170
日K : https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=114.jmm&klt=101&fqt=0&...
```

- `secid=114.jmm` 焦煤主连, `114.jm` 焦炭主连(市场号 114 = 大商所)
- 回显 `Access-Control-Allow-Origin`,浏览器可直连,前端窄条不经后端
- `f43`(最新价)/`f169`(涨跌额)是定点整数,按 `f59` 位小数还原;`f170`(涨跌幅)
  恒定除以 100,与 `f59` 无关。国内期货涨跌幅基准是**昨结算价**,不是昨收盘价,
  必须用 `f169`/`f170`,不能自己拿相邻日K收盘价相减
- 批量接口 `ulist.np` 对期货实测返回全 0,只能逐个 secid 单查
- 主力连续序列有换月跳空(实测 2026-08-19 一次性 +12.81%,超涨跌停板不可能
  是真实行情),曾经写过 `rollAdjustedPoints` 后复权处理——现已删除,因为成本卡
  的参考估算改用现货指数(见下),不再需要期货序列做基准换算。窄条本身只展示
  当前价和 sparkline,不受换月影响

## 2. CCTD 焦煤现货指数(CCP) — `coal_index.ts` + `blend_kit_server/src/coal_index.rs`

```
https://www.cctd.com.cn/api.php?op=echarts
```

- 中价·新华焦煤价格指数(CCP),发改委价格监测中心 + 新华社中国经济信息社编制,
  返回长协/现货/竞价三条子指数,**周频**,98 周历史(2024-09 至今),GET 无鉴权
- 只取 `PRICE2`(现货指数);字段全是字符串,要 `parse::<f64>()`
- **不回显 CORS 头**,浏览器直连会被挡,必须走 `blend_kit_server` 代理
  (`GET /api/coal-index`,公开路由、内存缓存 6 小时)——这是它和东财接口的
  关键差异,也是为什么这一路径需要后端而窄条不需要
- 现货指数不拼合约,没有期货那种换月跳空,不需要复权
- 发现过程:该接口不在任何静态 HTML 里能 grep 到,是打开浏览器 Network 面板
  看 CCTD「煤炭价格中心」页面运行时实际发的 XHR 才找到的。教训:判断"有没有
  可用接口"要看运行时流量,不能只 curl 抓静态源码做 grep——SPA/异步加载的页面
  数据从来不在初始 HTML 里
- 汾渭(sxcoal.com)首页也有几条现货指数,但没找到对应 JSON 接口(是 Next.js
  服务端直出,数据详情页锁在 Tableau 票据后面);生意社(100ppi.com)挂了 JS
  cookie 反爬,不易绕过。CCTD 是目前唯一现成可用的免费现货源

## 都只做参考,不进求解/导出/历史

无论期货还是 CCP,都只用于成本卡的"预测到厂价"展示,不改变 `blend_kit`
的求解输入,也不写入 `导出订单`/`保存方案`/历史记录——那些字段固定用
`result.cost` 的实际求解值。原因:

1. **基差**:两者都是全国性/标准品指数,用户实际煤种(中高硫山西煤为主)与
   之有价差,直接当成交价会错
2. **数据完整性**:导出/保存代表一次真实决策,不该混入一个可能因源站抖动
   而拿不到、且本质是猜测的数字

真正贴合用户煤种、可进求解的价格来源是`锚点煤`(用户在煤池标记 + 手动录价,
见 `priceDrift.ts`)——这是校准依据,两个外部指数只是"该去更新报价了"的提醒。

## 两者都可能随时失效

都是页面内部接口,不是公开 API,源站改版可能直接断。都做了优雅降级:
拿不到就跳过展示对应部分,不影响核心求解功能。CCTD 那条服务端缓存 6 小时,
失败时退回上一次成功缓存,避免源站抖动导致整条链路跟着抖。
